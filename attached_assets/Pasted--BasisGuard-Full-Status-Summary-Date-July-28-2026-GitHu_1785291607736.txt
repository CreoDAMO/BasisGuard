## 1. What BasisGuard Is

**BasisGuard** is a professional crypto tax compliance platform built for CPAs and power users. It treats every classification as an **audit-ready Position Record** with:

- A cited IRS authority  
- An IRC §6694 / Circular 230 confidence tier  
- A plain-language rationale  
- Immutable sign-off and supersession chains  

**Core differentiators vs generic tools (Koinly, CoinLedger, TokenTax):**

1. **Defensibility** — every position requires a real citation, not a vendor assumption  
2. **Guidance gaps** — DeFi/LP/bridge/NFT events are explicitly flagged as open-gap and held for preparer review  
3. **Wallet-by-wallet basis** — aligned with Rev. Proc. 2024-28  
4. **Evidence exports** — audit packages, CPA hand-off, comment-letter aggregates  

**Entity / commercial intent:** SSDF Inc. (Florida). Sellable as tax software (no federal license required unless e-filing is added). Payments designed around **Coinbase Commerce (USDC)**.

## 5. Current Production Blocker (Critical)

**Cross-origin auth.**

- App origin: `basisguard.site`  
- API origin: `basisguard-api.onrender.com`  

Clerk session cookies are **not** sent to a different site. Frontend calls use `credentials: "include"` only → API returns **401** → non-array JSON → pages crash with:

- `/positions` → `d?.map is not a function`  
- `/chains` → `e?.filter is not a function`  
- `/lots` → HTTP 401  
- `/transactions` → Unauthorized  

The on-screen “Clerk domain or proxy misconfiguration” text is largely a **generic error-boundary message**; the underlying failure is missing **Bearer tokens** on API requests.

**Required fix (Clerk cross-origin pattern):**

```ts
const token = await getToken(); // from useAuth()
fetch(`${API}/api/...`, {
  credentials: "include",
  headers: { Authorization: `Bearer ${token}` },
});
```

Apply to all authenticated fetches and the generated API client. Optionally harden with `Array.isArray(data) ? data : []` so failures degrade instead of white-screening.

Secondary checks: API not sleeping on free tier; CORS commas correct; frontend rebuilt after any `VITE_*` change (clear build cache).
